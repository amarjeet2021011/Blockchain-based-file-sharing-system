# File Securita

A blockchain-based file sharing system. Files are stored on IPFS via [Pinata](https://www.pinata.cloud/). Their links are recorded in an Ethereum smart contract (`contracts/Upload.sol`), which also tracks which addresses each owner has shared their files with. The React frontend connects through [MetaMask](https://metamask.io/).

> **Privacy note:** all data on a public blockchain is readable by anyone, and IPFS content is public to anyone who knows the CID. The contract's access control only governs what the app shows. Encrypt sensitive files before uploading them.

## Project layout

```
contracts/Upload.sol          Smart contract
test/Upload.test.js           Contract tests (Hardhat + Chai)
scripts/deploy.js             Deploys the contract and writes ABI + address to client/src/contract/
hardhat.config.js             Hardhat config (localhost + optional Sepolia)
client/                       React (Vite) frontend
  src/contract/Upload.json    Contract ABI (generated by deploy script)
  src/contract/addresses.json Contract address per chain ID (generated by deploy script)
```

## Prerequisites

- [Node.js](https://nodejs.org/) 18+ (20 or 22 recommended) and npm
- [MetaMask](https://metamask.io/download/) browser extension
- A [Pinata](https://app.pinata.cloud/developers/api-keys) API key (JWT) for file uploads

## Quick start (local Hardhat network)

```bash
# 1. Install dependencies
npm install
cd client && npm install && cd ..

# 2. Run the contract tests (optional)
npm test

# 3. Start a local blockchain (keep this terminal open)
npm run node

# 4. In a second terminal, deploy the contract to it
npm run deploy:local

# 5. Configure and start the frontend
cd client
cp .env.example .env        # then set VITE_PINATA_JWT
npm run dev                 # opens on http://localhost:5173
```

### Connect MetaMask to the local network

1. In MetaMask, add a network manually:
   - Network name: `Hardhat Local`
   - RPC URL: `http://127.0.0.1:8545`
   - Chain ID: `31337`
   - Currency symbol: `ETH`

   (The app also offers to add or switch to this network for you.)
2. Import one of the test accounts that `npm run node` prints, using its private key. Each one has 10,000 test ETH. These keys are public, so never use them on a real network.
3. Open the app, click **Connect MetaMask**, then upload files and use **Share** to grant access to another address.

> If you restart `npm run node`, the chain is reset. Run `npm run deploy:local` again. In MetaMask, open *Settings → Advanced → Clear activity tab data* so the account nonce resets.

## Deploying to Sepolia

1. Get some Sepolia ETH from a faucet.
2. Create a `.env` file in the project root:

   ```bash
   cp .env.example .env
   ```

   Set `PRIVATE_KEY` to the deployer account's private key, and optionally set `SEPOLIA_RPC_URL`. `.env` is git-ignored, so never commit real keys.
3. Deploy:

   ```bash
   npm run deploy:sepolia
   ```

   The script saves the address under chain ID `11155111` in `client/src/contract/addresses.json`. The frontend then picks it up automatically when MetaMask is on Sepolia.

## Frontend configuration (`client/.env`)

| Variable | Description |
| --- | --- |
| `VITE_PINATA_JWT` | Pinata JWT used for uploads (recommended) |
| `VITE_PINATA_API_KEY` / `VITE_PINATA_API_SECRET` | Alternative to the JWT |
| `VITE_IPFS_GATEWAY` | Gateway used to open files (default `https://gateway.pinata.cloud`) |
| `VITE_CONTRACT_ADDRESS` | Optional override for the contract address |

> `VITE_*` variables are bundled into the frontend JavaScript. For a public deployment, use a scoped Pinata key, or move the upload step behind a small backend.

## Contract API

| Function | Description |
| --- | --- |
| `add(url, fileType, fileName)` | Saves a file reference under the caller's address |
| `allow(user)` / `disallow(user)` | Grants or revokes `user`'s access to the caller's files |
| `display(owner)` | Returns `owner`'s files. Only works for the owner or a granted user |
| `shareAccess()` | Lists the addresses the caller has shared with, plus their status |
| `sharedWithMe()` | Lists the owners that currently share their files with the caller |
| `hasAccess(owner, user)` | Checks whether `user` can view `owner`'s files |
